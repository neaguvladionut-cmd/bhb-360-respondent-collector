# 360 Respondent Collector

Participant-facing, bilingual form for collecting a participant's 360 respondents correctly and downloading a standardized Excel workbook for the working consultant.

## Audience and purpose

This pack is for a 360 participant, not the consultant. It replaces an error-prone blank spreadsheet with a guided form that explains who to invite, validates details while they are entered and creates a file ready to email to the consultant.

The participant sees familiar language: **Autoevaluare**, **Manager**, **Peer**, **Subordonat** and **Stakeholder**. Production-only terms and quirks stay hidden.

## Workflow

1. Choose Romanian or English for the interface; Romanian is the default.
2. Enter the participant's own name and email. Self-evaluation is included automatically.
3. Add the required distinct Manager in the dedicated Manager section, then add any number of Peer, Subordonat or Stakeholder respondents.
4. Optionally open Adaugă criterii opționale and enter up to five participant criteria. The button keeps this secondary information out of the main flow unless it is needed.
5. Choose the questionnaire language for each person. This is separate from the interface language.
6. Review the clear errors and guidance. Ten respondents in total is the general recommendation; cohorts above 15 show a warning but remain allowed.
7. Download either the standardized participant workbook, or the blank large-list relations template for HR/client completion.

## Automation admission gate

1. **Existing input:** the participant's own identity and the respondent details they already supplied in a blank collection sheet.
2. **Steps removed:** interpreting spreadsheet columns, remembering the self row, checking the minimum/maximum, fixing roles/languages and rebuilding a malformed file.
3. **Finished replacement:** one readable standardized respondent `.xlsx`, ready to attach to the consultant's email.
4. **Errors made impossible or visible:** missing/distinct Manager, invalid names/emails/languages, duplicate participant/respondent pairs, optional criteria and clear guidance when a cohort grows beyond 15.
5. **Legacy app unchanged:** yes. This is a local sidecar and does not call, configure or write back to the production application.

## Inputs and finished output

| Surface | Accepted | Result |
|---|---|---|
| Participant form | One participant, automatic self-evaluation, required Manager plus any number of other respondents, valid two-letter language per person, optional five criteria | Normalized in-memory list |
| Large-list template | Blank participant–respondent relation workbook with Manager and criteria columns | template-relatii-360.xlsx, completed by HR/client and loaded into the internal importer |
| Download | A valid completed form | `respondenti-360-<participant>.xlsx`, ready for consultant handoff |

The form does not import an existing workbook, retain a draft or produce an audit receipt. `src/` is the canonical implementation. `deploy/` is generated by `npm run build` and must never be hand-edited.

## Privacy

All work happens locally in the browser. The pack needs no account, server, analytics or upload API. Participant and respondent data must not be sent over the network, placed in URLs, written to browser persistence or cached by a service worker. **Clear/reset** removes the in-memory working data.

## Diagnosis and recovery

Validation identifies the field and correction before download. Correct the marked field and try again. Closing, reloading or clearing the page removes the in-memory form and requires re-entry; it cannot remove a workbook already downloaded. The participant should send only the latest correct workbook to the consultant.

## GitHub Pages upload

The finished `deploy/` directory is the publishable pack. Upload **the contents of `deploy/`** to the root of its own public GitHub repository, then enable GitHub Pages from that repository's main branch and root directory. Assets use relative paths so the tool works at a repository subpath. Do not publish source workbooks, generated respondent files, real names/emails or test screenshots containing client data.

For a local preview, extract the pack and open `deploy/index.html` directly. The build bundles the application into a classic script so controls also work from a `file://` address; keep the full `deploy/` folder together.

## Intentional differences

- **From the old production app:** this is a safe collection bridge. It downloads a file for consultant handoff; it does not enroll respondents, send invitations or reveal that the old importer encodes self-evaluation as the first `Manager` row.
- **From the future platform:** the target platform should collect respondents inside a live 360 project and enroll them directly. This downloadable collector exists because the current production app cannot do that safely.
- **From the internal import builder:** this pack handles one participant and contains no project-wide identifier allocation, legacy reconciliation or production import export.

## Acceptance boundary

The authoritative acceptance list is the Architect decision gate in the review note (internal note, kept in the private workspace). The collector is accepted only as one half of the pair: its downloaded workbook must round-trip through the internal builder, pass privacy/accessibility/visual checks, and use synthetic fixtures only. It is not itself a production-app importer.

## Development verification

Run `npm run build` to regenerate the Pages pack and `npm run verify` to rebuild `deploy/`, execute the synthetic workbook/package suite and run the nested-subpath Chromium privacy/reset test. Verification binds copied styles/assets to `src/` and proves the classic direct-file bundle is the deterministic documented transformation of `src/core.js`, `src/app.js` and `src/index.html`. The browser test uses an existing local Playwright installation and never downloads dependencies; set `CODEX_PRIMARY_NODE_MODULES` if Playwright is installed outside normal Node resolution. A managed macOS sandbox may deny Chromium's Mach rendezvous service—in that case the command reports an explicit skip, and the browser test must be rerun outside that sandbox before release.
